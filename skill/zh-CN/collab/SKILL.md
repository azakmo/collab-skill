# 三方协同（框架目录 = 环境变量 `COLLAB_HOME`）

先读 `$env:COLLAB_HOME\README.md`（脚本用法、开关、退出码）。下文的 `$env:COLLAB_HOME` 就是框架所在目录。

## 核心原则：省 CC 的调用次数
CC 每调用一次模型，都要把整段上下文重新读一遍，所以 token 的大头是 CC 的调用次数，不是执行者的。CC 的价值在于想清楚并写清楚，不在于亲手写代码。四条硬规矩：
1. **任务说明写细**：一次写对，执行者就不用来回问，也不会做歪。
2. **附验收测试**：终审一条命令就能跑完，不逐行读代码。
3. **派出去就不盯**：后台运行，等完成通知，中间不看日志、不查进度。
4. **小活不派**：CC 自己 3 次以内的工具调用能做完的活（改几行、看一个小文件、跑一条命令），直接做。写任务说明再验收的成本比这还高。

## 派给谁（按资源稀缺度）
| 执行者 | 额度情况 | 派什么 |
|---|---|---|
| Gemini | 额度最多 | **大部分代码**：规格写清楚、有验收测试的实现、批量修改、脚本、编译、读资料 |
| Codex | 适度用 | 难的排查、跨模块集成、规格难写清楚的活、**初审 Gemini 的成果**、Gemini 返工两轮仍不过的活 |
| CC | 最紧张 | 拆任务、写规格和测试、做决定、终审、涉及真实环境的操作 |

**先读 `$env:COLLAB_HOME\roster.json`**：只能从里面已启用的执行者和已勾选的模型中选（派活脚本会硬性拒绝其他的）。上表是默认分工，用户在控制台里改过分层就以 roster 为准。

**写「评估」一节**（任务模板里有）：难度 1–3、预估 token、派给谁、理由、升级路径。
- 难度高于所有已启用执行者的 tier，或者同类任务返工两轮还不过：停下来**提醒用户**，说明哪类任务、现有模型哪里不够、建议在控制台加或换什么模型。
- 派活时脚本打出 `WARNING: task 难度 > tier`，就照上一条处理。

再看 `$env:COLLAB_HOME\ledger.csv` 里同类任务的历史表现：哪个执行者通过率高、token 少就优先派给它，有数据时以数据为准。

## 流程
1. **拆任务**：先按「小活不派」把小活挑出来自己做，其余拆成互不重叠的任务（同一个文件同一时间只给一个执行者）。
2. **建目录**：`& "$env:COLLAB_HOME\bin\init-collab.ps1" -Project <项目目录>`，写 `collab\brief.md`。
3. **写任务**：按 `collab\_templates\task.md` 写 `collab\tasks\T00n.md`，更新 `board.md`。
   - **背景写全**：执行者没看过任何聊天记录。
   - **「规格」一节写细**：接口和文件结构、输入输出示例（正常和异常各一个）、边界情况逐条写怎么处理、不要做的事。这一节决定执行者能不能一次做对。
   - **「验收测试」一节必须有**：每条验收条件写一个 `Check`，跑起来全部通过才算完成。测试要能在项目根目录直接运行、不依赖网络和真实环境（真实环境的验证由 CC 和用户自己做）。
   - **有界面、图片或视频画面产出的，「视觉验收」一节必须写**（模板里有）：写清截图目录、参考图、逐张清单，验收测试另加一条 Check 检查截图数量。清单要写成能对着图核对的事实（"示例数据下环形图约 80%""底栏不遮挡最后一张卡片""深色模式标题是白字"），不要写"好看"。流水线在测试全过后会让视觉审查员逐张看图，不过就带着问题打回返工；只靠测试，曾多次放过字符串被吃掉、比例画反、小组件被裁切的界面。截图方式：Android 用 Roborazzi/Robolectric（沙箱里能跑，不需要模拟器）；网页用无头 Edge（技能 headless-edge-test）；视频用 ffmpeg 抽关键帧。
   - 视觉验收审查的是"做得对不对"，不管"好不好看"。风格类的活（要用户挑审美的）先出样张给用户选，再动手。
   - **只能在宿主机跑的检查用 `HostCheck`**（模板里有）：起 HTTP 服务、开浏览器、监听端口这类，在执行者沙箱里跑不了（沙箱里 HttpListener 报"句柄无效"）。`HostCheck` 在沙箱里输出 `SKIP [本机]`，不算失败；流水线在宿主机跑时照常检查。
   - **派活前先空跑一遍测试**：在交付物还不存在（或放一个极简的假产物）时，在项目根目录跑一次验收测试，逐条看失败原因是不是"产物还没写"。如果有某条失败的原因是测试本身（命令调错、拿不到输出、路径不对），先修测试再派，否则会白返工一轮。测试里要调用 GUI 程序（msedge 等）时，用 `Start-Process -Wait -RedirectStandardOutput`，不要用 `&`。
   - **规格里的安全要求和「不要做的」也要有检查**：能用 grep 级别查的就写成 `Check`，比如不引外部资源、数据不拼进 `innerHTML`（只允许赋固定字符串，不准有 `${`、不准赋变量）、不出现 `eval`、不写死密钥。这样第 6 步的 Codex 初审就能省掉。
   - **有先后关系的任务写「依赖」字段**（如 `- 依赖：T002`）：流水线开工前会核对依赖任务已通过、交付的文件没被改过，不满足就不开工。「允许修改的文件」要写全，越界检查以它为准：漏写的文件被改了会判成越界。
   - 「执行者守则」原样保留。
4. **派活：用流水线，一批只叫醒 CC 一次**
   - **首选**：`& "$env:COLLAB_HOME\bin\run-batch.ps1" -Project <目录> -Tasks T001,T002,... [-MaxRework 2]`，放到后台跑（`run_in_background`）。每个任务自动执行"派活 → 跑验收测试 → 不过就把失败项追加进任务文件返工（最多 MaxRework 轮）→ 还不过就按「升级路径」换下一个执行者"，全部结束后只输出一张汇总表，CC 只被叫醒一次。
   - 执行者、时限、联网、工具链、升级路径都从任务文件的字段里读，所以这些字段必须写对（执行者一栏写 roster 里的 id）。
   - 结果：`PASS` 只抽查关键产物；`NO_TEST` 说明任务没写验收测试，CC 自己审；`NEEDS_CC` 说明整条升级路径都失败了，看 `collab/logs/<任务>.pipeline.json` 和回报，再决定重新拆分、自己做，还是提醒用户换模型。
   - 单个任务也可以用 `run-pipeline.ps1 -Project <目录> -Task T00n`。
   - 只有需要手动控制时，才直接调用下面的单次派活脚本：
     - 通用：`& "$env:COLLAB_HOME\bin\run-executor.ps1" -Executor <roster 里的 id> -Project <目录> -Task T00n [-Model m] [...]`
     - Gemini：`& "$env:COLLAB_HOME\bin\run-gemini.ps1" -Project <目录> -Task T00n [-TimeoutMin 20] [-Network] [-Toolchain android]`
     - Codex：`& "$env:COLLAB_HOME\bin\run-codex.ps1" -Project <目录> -Task T00n [-TimeoutMin 30] [-Network] [-Toolchain android]`
   - 派完就结束这一轮，等完成通知。**不轮询、不读日志、不中途检查**。
   - 中断不用 CC 管：执行者崩溃、卡死（连续 12 分钟没有日志输出）或反代断开时，流水线会自己等反代恢复，再用 `codex exec resume` 接着原会话做，不占返工轮数；原地空转（最近 6 次回复一字不差，退出码 5）则从头重开。手动派活遇到退出码不是 0/2/3 的，用 `run-executor.ps1 ... -Resume <err.log 里的 session id>` 续跑，不要从头重派。
   - 需要联网和编译环境的（下载依赖、Gradle、npm）照样下放，加 `-Network` 和 `-Toolchain`，时限放宽到 30–60 分钟。
5. **单次派活收到完成通知后先跑测试**（用流水线的话这一步已经自动做了）：`& "$env:COLLAB_HOME\bin\verify.ps1" -Project <目录> -Task T00n -Mark`
   - 全部 PASS：读回报的「未完成 / 疑问」一节，抽查一两处关键产物（运行一下、看一眼哈希或输出），就算通过。不逐行读代码。
   - 有「视觉验收」的任务：流水线已经让审查员逐张看过截图。CC 只看**一张**拼图 `collab\logs\<任务>.contact.png`，不逐张打开截图。pipeline.json 里 visual 是 `reviewer error` 的（审查员没跑成，比如反代断了），就手动跑 `visual-review.ps1 -Project <目录> -Task T00n`，或者自己对照清单看拼图。
   - 有 FAIL：直接写返工说明（贴上失败的那几行），派回同一个执行者。同一任务返工两轮还不过，就升级：Gemini → Codex → CC 自己做。
   - 退出码不是 0、或者没写回报：看回报或日志最后几行找原因，不要整份读。
6. **初审**：Gemini 做的实现，如果验收测试覆盖不了（比如安全性、架构是否合理），再派一个审查任务给 Codex。测试能覆盖的就不审，省 Codex 的额度。
7. **涉及真实环境**（服务器、路由器、线上部署、发给别人）：执行者一律不碰。CC 验收后把结论和证据给用户，等用户确认后再由 CC 执行，会断网的操作先问。
8. **收尾**：
   - 用 `ledger-mark.ps1` 登记（流水线和 `verify -Mark` 已经自动登记）。
   - 交接清单不用手动做：任务通过时流水线自动写 `collab\logs\<任务>.manifest.json` 和 `collab\handover.json`。pipeline.json 里有 `out_of_scope`（改了白名单外的已有文件，结果会是 NEEDS_CC）时，看一眼改动再决定：接受就把文件加进白名单后重跑，或者让人还原。`stray_files` 只是白名单外的新文件，确认无害即可。
   - **把 CC 自己的花销也记进去**：`& "$env:COLLAB_HOME\bin\cc-usage.ps1" -Since '<协同开始时间>' -Record -Project <目录> -Task 'CC(全程)'`。协同开始时记下当时的时间。
   - 向用户汇报：哪个任务由谁完成、测试结果、执行者和 CC 各花了多少（来自记账本）、哪些还没验证。

## 每个协同项目开一个新会话
CC 每次调用的成本和上下文长度成正比，长会话里做协同最贵。
- 用户说「请协同处理」时，如果当前会话已经很长（上下文超过约 15 万 token），或者前面聊的是不相关的事：建议用户开一个新会话，把需求、约束和项目路径写清楚，协同在新会话里做。
- 新会话里先读 README、roster 和记账本，不重复读之前的聊天；接手已有项目时先跑 `& "$env:COLLAB_HOME\bin\handover.ps1" -Project <目录>`，有文件在验收后被改过就先弄清楚是谁改的，再信 brief.md。
- **一个会话只做一批**：当前这批任务的返工、修补留在原会话；**新版本、新一批功能一律开新会话**，哪怕是同一个项目。上下文每一轮都会变长：一个真实项目在同一个会话里连续加了几轮功能，平均上下文从约 12 万涨到约 37 万 token，后面每次 CC 调用的成本约是开头的三倍。
- **交接靠文件，不靠聊天**：一批结束时（汇报之前）更新 `collabrief.md` 的「当前状态」一节（版本、已完成、用户拍板过的决定和原因、项目约定、已知问题）和 `board.md`。新会话的提示只写「项目路径 + 这次要做什么 + 先读 brief.md 和 board.md」，不要把旧聊天的内容抄进去。
- 用户在一批已经收尾的会话里又提新功能：先更新 brief.md，再开新会话，把新需求原话放进去，在原会话里回复一句新会话的链接，不要接着在原会话里做。

## 读资料、查日志、搜资料不自己读
- 大文件（大约几百行以上）、构建日志、陌生代码库、网页调研：用 `& "$env:COLLAB_HOME\bin\ask.ps1" -Project <目录> -Question '...' [-Files ...] [-Network]` 交给 Gemini，只读它交回的摘要。关键结论抽查一两处出处。
- 只限"读"。几十行就能看完的小文件不派。

## 执行者专用环境（`$env:COLLAB_HOME\executor`）
- 执行者启动时不带用户的个人技能列表，改为注入 `executor\AGENTS.md`（沙箱限制、PowerShell 坑、工作方式）和两个按需读取的技能（`headless-edge-test`、`pwsh-json-pitfalls`）。详见 README。
- 终审时如果发现执行者又在某个**通用**问题上反复试错（和具体任务无关、下个任务还会再踩），收尾时顺手补进 `executor\AGENTS.md` 或技能里。只放反复出现过的，保持短小。
- 任务说明里不用再重复这些通用坑，写任务特有的东西就行。

## 注意
- 脚本退出码：0 正常并有回报；2 没写新回报；3 超时被终止。日志在 `collab\logs\`，平时不读。
- Gemini 默认走 Codex 执行壳 + 一个 OpenAI 兼容（responses 格式）的反代，地址和密钥变量名在 roster.json 的 provider 里。反代没开时脚本会报错：这时请用户打开反代，或者把这个任务改派给 Codex。
- 开了联网后，执行者在技术上能访问任何地址，靠守则约束。所以涉及 SSH、部署或登录的活一律不派。
